# 2.8.0 Phase 0 回归基线

## 目的与边界

本目录冻结 `v2.8.0` 的人工回归基线，基线 commit 为
`44b8160efd590b05488d794df66f7ec711d65cb7`。它只记录验证方法、输入、
预期与实际结果；不修改 `SKILL.md`、模板或任何运行行为。

仓库没有自动化测试框架、生成脚本或包管理清单。因此本基线不制造形式化
自动化测试，而使用可重复的人工测试包。执行者必须使用支持 Agent Skills 的
真实宿主，并在每次执行后更新 `results.md`；未执行项必须保持“未执行”。

## 执行环境

- 仓库：`https://github.com/zyrobbie/travel-planner-skill`
- 基线：`main` 的 `44b8160efd590b05488d794df66f7ec711d65cb7`
- Skill：`SKILL.md` 及 `templates/`
- 需要的宿主能力：联网检索、真实对话、创建并打开 HTML/H5、Excel、PDF（如宿主声称支持）。

## 执行顺序

1. 运行静态文件检查：确认 tracked 文件完整、模板齐全、无合并冲突标记。
2. 使用 README 的一句 Prompt 安装方式安装到隔离的 skills 目录，确认文件与 frontmatter。
3. 在全新会话中以 `scenarios.md` 的输入逐条人工对话，保存逐轮文字记录和实际生成文件。
4. 对实际 HTML、Excel、PDF 分别执行生成、打开、内容与视觉检查；未生成或宿主不支持时记录“未执行”或“不支持”。
5. 在 `results.md` 记录命令/宿主、日期、实际行为、文件路径和结果。不要用预期替代实际。

## 状态定义

- **通过**：已实际执行，结果满足预期，且证据位置已记录。
- **失败**：已实际执行但未满足预期。
- **未执行**：当前环境尚未实际运行；不得视为通过。
- **不支持**：2.8.0 文档没有承诺该能力，或宿主没有该文件能力；不得视为通过。

详细用例见 [scenarios.md](scenarios.md)，当前记录见 [results.md](results.md)。
