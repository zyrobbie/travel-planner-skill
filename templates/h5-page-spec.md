# 轻量方向确认版 H5 规范

> 用途：交付物二。让客户判断"这是不是我想要的旅行？"
> 生成时机：阶段5（日程草案）客户需要可视化确认时。H5 不是新的规划阶段，也不是新的事实源——内容必须来自已确认主行程。

## H5 不承担

- 订单管理
- 付款跟踪
- 分钟级时间表
- 复杂地图
- 实时天气系统
- 完整景点资料库
- 敏感个人信息展示

## 标准页面结构（8 个区块）

1. **旅行标题、日期和团队**
2. **城市路线概览**
3. **方案的核心旅行主线**
4. **每日节奏**（每张卡片必须显示城市名 + 强度标签 + 主题介绍 + 当日体验摘要）
5. **必须保留体验**（**表格形式**，每个体验独立一行，含一句话亮点，禁止用箭头串）
6. **五项方向确认**：
   - 路线顺序
   - 整体节奏
   - 亲子体验比例
   - 自然与城市平衡
   - 关键大交通
7. **修改意见**（输入区）
8. **复制确认摘要**（一键复制按钮）

## 区块 4「每日节奏」渲染规范

每张日卡片必须包含且不限于以下信息：

- **日期标签**：例 `D2 2/4 周三`（短色块，宽度自适应内容，不得使用会被截断的固定宽度）
- **强度标签**：轻/中/强/极强，**短色块**，≤3 个汉字，宽度按内容自适应
- **城市明示**：城市字段必须出现在卡片标题区，格式如「吉隆坡 Kuala Lumpur · 地标与团年」
- **主题介绍**：一句话，必须包含城市名（例：吉隆坡都市轻量日，完成地标打卡和除夕守岁）
- **当日体验摘要**：可点开展开的折叠区，列出当日必保体验

**禁止的渲染方式**：

- 强度标签使用固定像素宽度（会被不同字符宽度截断）
- 城市名藏在描述文字里、卡片标题不出现城市
- 主题介绍省略城市，直接写「地标与团年」

## 区块 5「必须保留体验」表格规范

**必须用 `<table>` 渲染，禁止用箭头串（→）合并**。

表格列（最少 4 列，H5 可在移动端折叠部分列）：

| 列 | 内容 | 来源字段 |
|----|------|----------|
| 体验名称 | 中文可识别名（英文/当地名） | 每日必保体验.体验名称 |
| 城市 | 中文可识别名 | 每日必保体验.城市 |
| 时段 | 上午/下午/傍晚/夜间 | 每日必保体验.时段 |
| 亮点简介 | 一句话，≤40 字 | 每日必保体验.亮点简介 |

可选列：预估时长、是否必保（可加颜色色块：必保=实心、推荐=半透明、可选=边框）

按「所属日期」分组排序，分组标题显示日期与星期。表格在移动端允许横向滚动，但**不得**让列宽溢出到文字截断或重叠。

## 手机适配校验清单（生成 H5 后必须逐项检查）

生成 H5 之前与之后各校验一次，**未通过禁止交付**：

1. **视口设置**：`<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0">`
2. **断点**：使用 CSS `@media (max-width: 480px)` 覆盖移动端样式
3. **强度标签宽度**：使用 `padding: 4px 10px; width: fit-content; min-width: 0; white-space: nowrap;` —— 严禁固定 `width: 48px` 之类硬编码
4. **文字截断防御**：
   - 所有短色块标签必须用 `display: inline-block; max-width: 100%;` 包裹容器
   - 中文 + 英文混排时，验证不会出现"除夕 中"被截断为"除夕 中"漏字（按内容长度自适应宽度）
   - 长文本使用 `word-break: break-word; overflow-wrap: anywhere;`
5. **inline 排版重叠防御**：
   - 任何「短色块 + 标题」组合，必须用 flex 布局 + `gap` + `flex-wrap: wrap`，**不得**让色块和标题在窄屏下挤在同一行导致重叠
   - 卡片 padding 至少 `12px 16px`
6. **触控区域**：所有可点击元素 ≥44×44px
7. **字体大小**：正文 ≥14px，标题 ≥16px
8. **图片**：使用 `max-width: 100%; height: auto;`，禁止固定像素高度
9. **表格**：在 ≤480px 视口下：
   - 允许 `overflow-x: auto` 横向滚动
   - 不得用 `text-overflow: ellipsis` 截断亮点简介（会丢信息）
   - 移动端可折叠「城市」「时段」列到二级展开
10. **真实设备抽样**：在 iPhone SE（375px）、iPhone 14（390px）、iPhone 14 Pro Max（430px）、Android 中端（360px）四个宽度下截图核对

## 生成后必做的三项检查

- [ ] D2、D3、D5 等含中文强度标签的卡片，文字是否完整（例：「除夕 中」不被截断为「除夕 中」）
- [ ] D5 这种「色块 + 长标题」组合在 375px 视口下是否换行合理、无重叠
- [ ] 必保体验是否真的渲染为 `<table>` 而非箭头串

## 技术规范

- 移动端优先
- 尽量生成可独立打开的单文件（单个 .html，CSS/JS 内联）
- 重要图片可内嵌（base64）
- 不依赖复杂后端
- 触控区域足够大（≥44px）
- 字体和信息层级清晰
- 内容必须来自已确认主行程，并在页脚标注版本号

## 数据来源

页面数据读取自 SOP 沟通档案末尾的 6 张 H5 数据接口工作表（见 h5-data-sheets.md）：

- `项目设置` — 基础信息
- `每日行程` — 每日主表（含城市、强度、主题、体验 id 集合）
- `每日必保体验` — 体验明细表（必保体验表格区块的**唯一数据源**）
- `酒店住宿`
- `图片素材`

字段顺序以该模板为准，H5 生成程序严格按列序读取。
