# 三档 HTML 行程文档交付规范

## 共用技术与交付规则

三个档位都必须把已确认的方案写成真实、独立、UTF-8 编码的单文件 `.html`，保存到本次任务的输出目录。不得以代码块、Markdown、页面说明或不存在的文件代替。文件名使用 ASCII，例如 `quick-trip-advice.html`、`detailed-trip-plan.html`、`full-trip-itinerary.html`。

生成后先实际打开并检查，再向客户说文件已完成。最低检查包括：文件存在且非空；浏览器能打开且主内容非空；中文无 `�`；链接可点击；375px 宽度无页面级横向溢出；桌面端卡片与表格无截断或重叠；console 无 error；打印预览可读。CSS 与必要 JS 内联，页面不依赖本地开发服务或外部构建环境；提供 `@media print`，隐藏仅交互的按钮和输入区。

### 本地 HTML 验收方式降级

优先由 Agent 使用可用浏览器完成上述检查。若宿主安全策略阻止 Agent 打开本地 HTML，先完成文件存在、非空、UTF-8、关键内容、链接与结构等静态检查，并如实说明自动浏览器不可用；随后请用户本人打开文件检查。用户明确确认页面显示正常后，可将“用户侧人工视觉验收”记录为通过，并继续后续交付。不得仅凭静态检查自行宣称视觉验收通过；用户已经明确确认时不得重复要求确认。

这只是验收方式降级，不是交付物降级：不把未执行的 DOM 宽度、console error/warning 或精确视口截图写为通过。PDF/Excel 的交付级降级规则见下文。

HTML 只能陈述已确认事实、明确标注的估算或待确认事项。不得编造实时价格、库存、可订状态或已完成的预订。只提供推荐、比较、官方入口和用户自行下单核对项；不得创建、锁定、提交、确认订单或付款。

同一任务如还生成 Excel，必须先完成 HTML 的真实文件与检查，再生成 Excel；两个文件的日期、路线、城市、住宿、交通、风险、待确认事项与来源必须一致。

## 快速档

完成快速答复后自动生成简明 HTML，至少包含：用户问题/旅行背景、核心建议、必要时 2—3 个推荐方案与取舍、风险/限制/待核实事项、实际使用的有效来源链接。生成并检查成功后，询问：

> HTML 版本已经生成并检查完成。你还需要我另外生成一份规划 Excel 吗？

客户已在同一请求明确需要 Excel 时不重复询问，但仍严格按 HTML 后 Excel 的顺序。客户拒绝或未选择 Excel 时不得生成 Excel；快速档不得生成内部 SOP 档案，也不得为表格臆造信息。

## 详细档

在“基本条件 → 旅行方向 → 完整方案”的第三步形成完整方案后自动生成 HTML。至少包含：行程概览、路线与城市顺序、每日行程或节奏、交通建议、住宿区域或具体酒店建议、重点体验、预订优先级、风险、Plan B、待确认事项和有效来源链接。

检查成功后才询问是否需要一份面向旅行者的规划 Excel。客户明确需要才生成；客户拒绝则只交付 HTML。不得生成全流程内部阶段档案、团队治理表或无意义空 Sheet。

## 全流程策划

保留原有方向确认和完整交付流程。原方向确认 H5 是本档默认的独立 HTML 实现，面对客户统一称为“HTML 行程文档”；继续遵守 `h5-page-spec.md`、H5 数据接口与方向确认顺序。不得削弱路线、每日安排、多人约束、交通、住宿、体验、风险、订单核对或预订优先级。

客户确认方向后，冻结最终主行程并在临时工作区从同一份已确认 HTML/主行程生成 PDF、客户简明版 Excel 和 SOP 沟通档案 Excel。PDF 规则见 `pdf-delivery.md`。逐个真实打开、检查后，只有四份文件均通过才可作为正式矩阵交付。确认后发生修改时，必须同步重新生成和检查四份文件。

## Excel 真实验收

快速或详细档客户选择 Excel 时，生成一份用户版 `.xlsx`，并在独立表格工具中打开或导入。检查每张非空 Sheet 的中文、表头、日期、货币、链接、列宽/换行、公式错误、空白与分页；再独立渲染并人工检查每一页。全流程客户简明版与 SOP 档案 Excel 也必须分别完成此验收。无头 LibreOffice 中文渲染问题不是唯一裁判；可使用真实表格应用检查。

## 统一正式交付降级

HTML 是唯一不可降级的正式文件：若 HTML 无法可靠生成或由 Agent/用户完成实际检查，停止文件交付，不得用 Markdown、CSV、JSON、代码块或页面说明代替。

全流程策划中，只要 PDF 无法可靠生成、打开、提取或逐页检查，或任一 Excel 无法可靠生成、打开、读取或核对，正式交付统一改为一份完整 HTML。PDF 成功但 Excel 失败、Excel 成功但 PDF 失败、或仅一个 Excel 成功时，均不得混合交付任何 PDF/Excel。失败文件只可留在独立 evidence/work，不得在正式交付目录或清单中出现。

快速或详细档中，客户选择 Excel 后如 Excel 无法可靠生成或检查，也只正式交付完整 HTML。HTML 必须补足原本需要由 Excel 承载的行程、预订清单、风险、待确认事项和打印内容。

使用以下提示，并按实际失败格式把“PDF、Excel”缩为“Excel”或相应格式：

> 当前环境不能可靠生成或检查完整的 PDF、Excel 文件，因此本次改为一份完整 HTML。行程、预订清单、风险提示和可打印内容都已保留。
