# 一致性检查与最终验收

## 档位交付检查

- [ ] 快速与详细：HTML 已真实生成、打开并检查后，才询问是否需要 Excel；客户拒绝时没有生成 Excel。
- [ ] 快速与详细：客户明确需要 Excel 时，HTML 在先、用户版 Excel 在后；Excel 已独立打开、渲染和人工检查。
- [ ] 全流程：方向确认 H5 作为 HTML 行程文档保留原有方向确认与后续 Excel 顺序。
- [ ] 三档 HTML 均为独立 UTF-8 文件；优先完成移动端、桌面端、console 与打印检查。若宿主安全策略阻止 Agent 打开本地文件，按 `html-delivery.md` 完成静态检查与用户侧实际打开确认，并把未执行的自动检查如实记录；没有虚构价格、库存或采购完成状态。

## 一、三份交付物一致性检查

所有交付必须来自同一个已确认主行程。逐项核对三份交付物（客户简明版 Excel / 方向确认 H5 / SOP 沟通档案）中的以下字段是否一致：

- [ ] 起止日期
- [ ] 星期
- [ ] 城市顺序
- [ ] 停留晚数
- [ ] 每日主题
- [ ] 住宿
- [ ] 夜船归属
- [ ] 跨城交通日期
- [ ] 必须项目
- [ ] 可选项目
- [ ] 待确认事项
- [ ] 版本号

客户简明版、H5 和 SOP 档案不能各自维护一套互相矛盾的数据。

## 二、H5 数据接口关联完整性检查

生成 H5 前，核对 6 张 H5 数据接口工作表之间的关联一致性：

- [ ] 「每日行程」列4（体验id集合）中的每个 id，都能在「每日必保体验」列1（id）中找到对应行
- [ ] 「每日必保体验」列2（所属日期）都能在「每日行程」列1（日期）中找到对应日
- [ ] 「每日必保体验」列3（城市）与「每日行程」同行的列3（城市）一致
- [ ] 每个 id 在「每日必保体验」中唯一，无重复、无空值
- [ ] 「每日行程」列3（城市）无空值，列7（主题介绍）均包含城市名
- [ ] 「每日必保体验」列6（亮点简介）均 ≤40 字且非空

关联断裂会导致 H5 日卡片展开无数据或体验表格缺行，发现即修，不得带错生成。

## 三、最终验收标准（12 条，全部满足才能宣布完成）

- [ ] 1. 客户能解释为什么这样安排
- [ ] 2. 团队需求得到平衡
- [ ] 3. 路线、节奏和体验方向已经确认
- [ ] 4. 所有可能阻断出发的 A 类事项都进入清单
- [ ] 5. 酒店、保险、证件和国际交通没有遗漏
- [ ] 6. 未知信息没有被伪装成事实
- [ ] 7. 日期、地理、交通、住宿和订单经过核对
- [ ] 8. 客户简明版能在 3 分钟内看懂
- [ ] 9. H5 能够用于确认旅行方向
- [ ] 10. SOP 档案足够让其他规划师继续工作
- [ ] 11. 三份交付物核心事实一致
- [ ] 12. 如果平台不能生成文件，已经明确说明限制，没有把脆弱原型包装成成品
