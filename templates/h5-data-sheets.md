# 标准 H5 数据接口（6 张工作表）

> 位置：SOP 沟通档案末尾。它们是 H5 数据接口，不是独立沟通阶段。
> 字段顺序必须严格保持，H5 生成程序依赖此顺序读取。

## Sheet `填写说明`

内容：模板使用方法、同步原则和字段含义。

## Sheet `项目设置`

字段顺序（固定）：

| 列序 | 字段 |
|------|------|
| 1 | 字段 |
| 2 | 填写内容 |
| 3 | 说明 |

## Sheet `每日行程`

> 这是「每日主表」，每行对应一天。H5 每日节奏区块按此表渲染。
> 城市字段（列3）必填且必须出现在用户可见文字中，禁止省略。
> 列4 每日核心体验的 id 集合，与「每日必保体验」Sheet 的 id 字段对应（用 `,` 分隔，如 `e1,e2,e3`）。

字段顺序（固定）：

| 列序 | 字段 | 必填 | 说明 |
|------|------|------|------|
| 1 | 日期 | 是 | YYYY-MM-DD |
| 2 | 星期 | 是 | 一/二/三/.../日 或 Mon/Tue... |
| 3 | 城市 | 是 | **必填**，中文可识别名 + 英文（格式：吉隆坡 Kuala Lumpur），H5 必须在每日卡片标题中显示此字段 |
| 4 | 体验id集合 | 是 | 与「每日必保体验」Sheet 的 id 字段对应，多个用 `,` 分隔 |
| 5 | 强度标签 | 是 | 轻/中/强/极强，H5 渲染为短色块标签（≤3 个汉字） |
| 6 | 当天主题 | 是 | 卡片主标题（≤10 字） |
| 7 | 主题介绍 | 是 | 一句话介绍，必须包含城市名（例：吉隆坡抵达与暖身，市内轻量移动） |
| 8 | 显示在总览 | 是 | true/false |
| 9 | 备注 | 否 | Plan B / 注意事项 |

## Sheet `每日必保体验`

> 这是「必保体验明细表」，每个独立体验占一行。H5 必须以**表格**（非箭头串）渲染此表，每个体验独立一行，含一句话亮点。
> 此 Sheet 是 H5「必须保留体验」区块的唯一数据源。
> id 字段需与「每日行程」Sheet 列4 关联。

字段顺序（固定）：

| 列序 | 字段 | 必填 | 说明 |
|------|------|------|------|
| 1 | id | 是 | 简短唯一标识（例：e1、e2），与「每日行程」列4 对应 |
| 2 | 所属日期 | 是 | YYYY-MM-DD，与「每日行程」列1 对应 |
| 3 | 城市 | 是 | 与「每日行程」列3 一致，便于表格独立阅读 |
| 4 | 体验名称 | 是 | 中文可识别名（英文/当地名）格式，按命名可识别性规则 |
| 5 | 体验类型 | 是 | 景点/活动/餐厅/街区/徒步/演出/交通 等 |
| 6 | 亮点简介 | 是 | **一句话亮点**（≤40 字），必须说清「是什么 + 为什么必去 + 适合谁」三要素之一 |
| 7 | 预估时长 | 否 | 例：1.5h / 2—3h / 全天 |
| 8 | 是否必保 | 是 | 必保/推荐/可选 |
| 9 | 时段 | 否 | 上午/下午/傍晚/夜间，H5 用作表格分组 |
| 10 | 地图搜索词 | 否 | Google Maps 搜索词 |
| 11 | 备注 | 否 | 天气敏感、年龄限制等 |

## 平台限制与正式交付

如平台无法直接生成或可靠检查 HTML、PDF 或 Excel，不得声称已经创建或交付失败文件。完整 Sheet 结构、可复制表格、结构化 JSON/CSV、H5 页面内容规范和文件字段仅可作为内部中间数据，不得作为正式替代交付。

HTML 无法可靠生成或实际检查时停止文件交付；PDF 或 Excel 无法可靠完成时，按 `html-delivery.md` 统一正式交付为完整 HTML。不得把成功文件和失败文件混合列入正式交付清单。
